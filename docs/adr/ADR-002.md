# ADR-002: Technology Stack

- **Status:** Accepted
- **Date:** 2026-08-05
- **Decision Makers:** CareerOS Engineering
- **Version:** 1.0
- **Supersedes:** None
- **Superseded By:** None

---

# Context

CareerOS is being built as a modern SaaS platform consisting of multiple applications that share a common domain model and engineering standards.

The platform currently consists of:

- Web Application
- Backend API
- Browser Extension
- Shared Packages
- Developer CLI (Backlog CLI)
- Documentation
- CI/CD Infrastructure

The technology stack should:

- Be fully TypeScript-first
- Minimize context switching between applications
- Support long-term maintainability
- Enable rapid feature development
- Support strong typing across the entire platform
- Be cloud-agnostic
- Integrate well with modern tooling
- Provide an excellent developer experience
- Scale from MVP to production

A consistent stack also simplifies onboarding, testing, documentation, automation, and AI-assisted development.

---

# Decision

CareerOS will standardize on a **TypeScript-first technology stack** across the entire platform.

The selected technologies prioritize:

- Simplicity
- Type safety
- Performance
- Maintainability
- Strong ecosystems
- Long-term stability

# Frontend Stack

## React

React is the standard UI framework.

Reasons:

- Mature ecosystem
- Large community
- Excellent TypeScript support
- Component-based architecture
- Strong tooling
- Familiar developer experience

---

## Vite

Vite is the build tool for frontend applications.

Reasons:

- Extremely fast development server
- Fast production builds
- Excellent TypeScript support
- First-class React integration
- Plugin ecosystem
- Low configuration

---

## TypeScript

TypeScript is mandatory across the repository.

Reasons:

- Compile-time safety
- Shared types
- Better refactoring
- Improved IDE support
- Strong API contracts
- Reduced runtime bugs

Strict mode is enabled.

---

## Tailwind CSS

Tailwind CSS is the styling system.

Reasons:

- Utility-first workflow
- Consistent design system
- Small production bundles
- Rapid UI development
- Easy theming

Custom design tokens will extend Tailwind where necessary.

---

## React Router

React Router manages client-side routing.

Reasons:

- Industry standard
- Nested routing
- Lazy loading
- Mature ecosystem

---

## React Hook Form

Used for form state management.

Reasons:

- Excellent performance
- Minimal re-renders
- Native TypeScript support
- Tight integration with Zod

---

## Zod

Zod validates all external data.

Reasons:

- Runtime validation
- Static type inference
- Shared schemas
- API validation
- Form validation

All user input and external data must be validated using Zod.

---

## TanStack Query

TanStack Query manages server state.

Reasons:

- Intelligent caching
- Request deduplication
- Automatic retries
- Background refetching
- Optimistic updates
- Excellent TypeScript support

Server state should never be managed manually when TanStack Query is appropriate.

# Alternatives Considered

## Next.js

Advantages:

- SSR
- Built-in routing

Rejected because:

- CareerOS primarily targets a client-side dashboard.
- Vite provides faster local development and greater flexibility.
- Backend responsibilities are intentionally separated into Hono.

---

## Express

Advantages:

- Mature ecosystem

Rejected because:

- Larger API surface
- Less optimized for modern TypeScript development
- Hono provides a leaner, standards-based approach

---

## Drizzle ORM

Advantages:

- Lightweight
- SQL-centric

Rejected because:

- Prisma offers stronger tooling, migrations, and developer experience for the current team.

---

## CSS Modules / Styled Components

Rejected because:

- Tailwind provides a more consistent, scalable design workflow.

---

## GraphQL

Advantages:

- Flexible querying

Rejected because:

- REST better matches current product requirements.
- Simpler contracts.
- Easier documentation.
- Lower operational complexity.

---

# Consequences

## Positive

- Consistent developer experience
- Unified language across the stack
- Excellent tooling
- Strong type safety
- Simplified onboarding
- Shared validation
- High code quality
- Easier automation
- Better AI-assisted development

---

## Negative

- Requires familiarity with modern TypeScript ecosystem
- Multiple tools increase initial setup complexity
- Strict typing introduces additional development discipline

These trade-offs are considered acceptable given the long-term benefits.

---

# Compliance

The following rules are mandatory:

- All production code is written in TypeScript.
- All external input is validated with Zod.
- All database access goes through Prisma.
- All frontend applications use React.
- All frontend builds use Vite.
- Browser extensions use WXT.
- APIs are implemented using Hono.
- Shared logic belongs in shared packages.
- Docker is used for deployment.
- CI must pass before merging.

Technology changes require a new ADR.

# Decision Summary

CareerOS will adopt a **TypeScript-first, React-based, Hono-powered, PostgreSQL-backed technology stack** managed within a **Turborepo monorepo** using **pnpm Workspaces**. Supporting technologies such as Vite, Tailwind CSS, Prisma, WXT, Firebase Authentication, TanStack Query, Zod, Docker, Coolify, and GitHub Actions provide a consistent, maintainable, and scalable foundation for the platform.
