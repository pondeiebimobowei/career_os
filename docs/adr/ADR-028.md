# ADR-028: AI-Assisted Development

- **Status:** Accepted
- **Date:** 2026-08-05
- **Decision Makers:** CareerOS Engineering
- **Version:** 1.0
- **Supersedes:** None
- **Superseded By:** None

---

# Context

CareerOS is intentionally designed to be developed with the assistance of modern AI coding tools.

These include:

- IDE coding assistants
- CLI coding agents
- Code generation models
- Documentation assistants
- Code review assistants
- Refactoring assistants

AI significantly improves engineering productivity by accelerating repetitive engineering tasks.

However, AI systems can also:

- hallucinate APIs,
- violate architecture,
- ignore existing abstractions,
- introduce security vulnerabilities,
- duplicate logic,
- generate inconsistent implementations.

Without clear operational rules, AI-generated code quickly becomes inconsistent with the architecture.

CareerOS therefore requires a formal policy describing how AI participates in software development.

---

# Decision

CareerOS adopts an **AI-Assisted Development** model.

AI is treated as an **engineering collaborator and productivity multiplier**, not as an autonomous engineer.

Humans retain responsibility for all architectural decisions, implementation quality, security, correctness, and releases.

---

# Goals

The AI development model should:

- Increase engineering velocity.
- Reduce repetitive work.
- Preserve architectural consistency.
- Improve documentation quality.
- Support deterministic workflows.
- Encourage responsible AI usage.
- Keep humans accountable for final decisions.

---

# Core Principle

AI assists engineering.

AI does not replace engineering.

Every significant engineering decision remains a human responsibility.

---

# Engineering Responsibilities

## AI May

- Generate code.
- Generate tests.
- Draft documentation.
- Explain existing code.
- Suggest refactorings.
- Identify potential bugs.
- Recommend optimizations.
- Generate pull request descriptions.
- Generate commit messages.
- Generate release notes.

---

## Humans Must

- Approve architecture.
- Review generated code.
- Validate correctness.
- Ensure security.
- Verify performance.
- Approve pull requests.
- Approve releases.
- Accept responsibility for production changes.

Responsibility cannot be delegated to AI.

---

# Repository-First Workflow

AI operates within the repository workflow.

```text
Backlog

↓

Issue

↓

AI Context

↓

Implementation

↓

Review

↓

Merge
```

AI should never invent work outside the approved backlog.

---

# Backlog Integration

AI begins implementation from CBS issues.

Example:

```bash
pnpm backlog:next
```

returns:

- issue,
- acceptance criteria,
- dependencies,
- related files,
- implementation context.

AI should use this structured context rather than inferring requirements from GitHub alone.

---

# Architecture Compliance

AI-generated code must comply with:

- ADRs
- Engineering Playbook
- Layered Architecture
- Feature-Based Structure
- Domain Model
- Repository conventions

Architecture is never inferred; it is followed.

---

# Coding Standards

AI-generated code must follow established project standards, including:

- SOLID principles
- DRY
- KISS
- YAGNI
- Strong typing
- Consistent naming
- Clear abstractions

Generated code is held to the same standard as human-written code.

---

# AI Scope

AI should focus on implementation tasks such as:

- business logic,
- UI components,
- tests,
- documentation,
- migrations,
- parser implementations,
- refactoring.

AI should avoid making product or architectural decisions without explicit guidance.

---

# Pull Requests

AI may generate:

- PR titles,
- descriptions,
- summaries,
- checklists,
- testing notes.

Human reviewers remain responsible for evaluating and approving pull requests.

---

# Code Reviews

AI may assist by:

- identifying bugs,
- suggesting improvements,
- detecting duplication,
- recommending refactoring.

AI feedback supplements, but does not replace, human code review.

---

# Testing

AI may generate:

- unit tests,
- integration tests,
- test data,
- mocks,
- fixtures.

Generated tests must be executed and reviewed before acceptance.

---

# Documentation

AI should update documentation whenever implementation changes affect:

- architecture,
- APIs,
- workflows,
- user behavior,
- engineering processes.

Documentation generation should be reviewed for accuracy.

---

# Refactoring

AI may propose refactoring when it:

- reduces duplication,
- improves readability,
- simplifies architecture,
- preserves behavior.

Large-scale refactoring should be reviewed before implementation.

---

# Security

AI-generated code must be reviewed for:

- authentication,
- authorization,
- input validation,
- secrets,
- dependency risks,
- injection vulnerabilities,
- data exposure.

Security review remains a human responsibility.

---

# Performance

AI may suggest performance improvements.

Performance changes should be validated through measurement rather than assumption.

---

# Error Handling

AI-generated code should:

- fail predictably,
- provide useful errors,
- preserve system consistency,
- avoid silent failures.

Generated error handling should align with project conventions.

---

# Dependency Management

AI should prefer:

- existing project libraries,
- shared packages,
- existing abstractions.

New dependencies require human evaluation.

---

# Deterministic Development

AI should rely on repository artifacts rather than assumptions.

Preferred inputs include:

- backlog YAML,
- ADRs,
- architecture documentation,
- engineering playbook,
- existing codebase.

Repository documentation takes precedence over model assumptions.

---

# Automation

AI integrates with repository tooling.

Examples:

```bash
pnpm backlog:next
```

```bash
pnpm backlog:start APP-001
```

```bash
pnpm backlog:pr APP-001
```

AI should use project tooling whenever available rather than reproducing its functionality.

---

# Human Review

Every AI-generated change requires human review before merging.

Review includes:

- correctness,
- architecture,
- testing,
- documentation,
- security,
- maintainability.

AI-generated code is never merged without review.

---

# AI Limitations

AI should not:

- bypass branch protection,
- modify production directly,
- approve its own pull requests,
- redefine architecture,
- ignore ADRs,
- create undocumented features,
- alter backlog priorities,
- override engineering standards.

These responsibilities remain with human contributors.

---

# Continuous Learning

Improvements to AI workflows should be documented through:

- ADRs,
- engineering documentation,
- tooling updates,
- prompt improvements.

AI usage evolves alongside the engineering process.

---

# Alternatives Considered

## Human-Only Development

Rejected because:

- lower productivity,
- slower iteration,
- repetitive work.

---

## AI-First Autonomous Development

Rejected because:

- unacceptable architectural risk,
- inconsistent quality,
- security concerns,
- lack of accountability.

---

## Unstructured AI Usage

Rejected because:

- inconsistent outputs,
- poor maintainability,
- reduced predictability.

---

# Consequences

## Positive

- Faster implementation.
- Improved documentation.
- Higher engineering productivity.
- Better onboarding.
- Reduced repetitive work.
- Consistent AI workflows.

---

## Negative

- Requires disciplined review.
- Prompt quality affects output.
- Developers must understand AI limitations.
- Tooling requires ongoing maintenance.

These trade-offs are acceptable.

---

# Compliance

The following rules are mandatory.

- AI acts as an engineering assistant, not an autonomous engineer.
- Humans retain responsibility for all architectural and production decisions.
- AI-generated code complies with project ADRs and engineering standards.
- Every AI-generated change is reviewed before merge.
- AI works from repository-defined backlog context.
- AI should reuse existing abstractions before creating new ones.
- Security, correctness, and architecture are always validated by humans.
- AI must not introduce undocumented functionality outside the approved backlog.

Changes to the AI-assisted development model require a new ADR.

# Decision Summary

CareerOS adopts an **AI-Assisted Development** model in which AI serves as a productivity-enhancing engineering collaborator while humans remain fully accountable for architecture, correctness, security, code quality, and production readiness. AI operates within the repository-first workflow, using CBS-backed backlog definitions, ADRs, and project tooling as its primary context. All AI-generated work must conform to established engineering standards, undergo human review, and integrate through the same development lifecycle as human-authored code.
